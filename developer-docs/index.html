開発の流れ

コードを書いてから公開されるまで、開発版は本人のアプリ内で試せます。公開版は審査で承認されたバージョンだけが利用者に配布されます。

  1. 01
    SDKを準備する

    開発キットを展開し、Node.js 22以降の環境を用意します。

  2. 02
    TypeScriptで機能を作る

    UI、状態、イベント、本人データAPIを組み合わせます。必要な権限だけを宣言します。

  3. 03
    自分のCIT Hubで確認する

    生成した拡張機能を開発者コンソールへアップロードし、自分のアプリ内で動作を確認します。

  4. 04
    審査へ提出する

    機能と変更内容を説明して提出します。承認前の開発版は一般公開されません。

安全性とデータ範囲

拡張機能は独立した実行環境で動き、画面はアプリのネイティブ部品で描画します。自由なHTMLやネイティブコードを直接実行する仕組みではありません。

拡張機能から取得できない情報
Portal/Manabaのパスワード、OTP秘密鍵、Cookie、CIT Hubのセッショントークン、他の利用者の個人データにはアクセスできません。本人データも宣言した権限と端末に取得済みの範囲に限ります。
  • 外部通信はHTTPSとmanifestで宣言したホストに限定されます。
  • OS権限の要求や写真・ファイルへのアクセスには利用者の操作が必要です。
  • 拡張機能APIサーバーは提出されたプログラムを実行しません。
  • 未対応のAPIは公開されず、互換性検査で起動が拒否されます。

テストと公開

拡張機能名、説明、権限、変更内容を確認してから審査へ提出してください。審査後に公開された版は固定され、開発版のアップロードだけでは一般ユーザーへ配布されません。

実装状況について
本ドキュメントは現行実装の範囲を説明します。計画中の機能やSDK型定義だけのAPIは、利用可能なAPIとして扱いません。各APIの正確な条件はAPIリファレンスをご確認ください。
